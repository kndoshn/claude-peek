# claude-peek 設計

Claude Code の中で、ファイル・フォルダー・Git・コマンドの出力を覗き、必要な箇所だけを出どころ付きで Claude に渡す mod。リポジトリは `kndoshn/claude-peek`、プラグイン名は `peek`。

## 目的

Claude に情報を渡すたびに、別のタブで `la`・`tree`・`pwd`・`gs`・`gd`・`glo`・`glow`・`cat` を実行し、出力の一部をコピーして貼る作業をなくす。タブを閉じ忘れたり、別の repo のタブで作業したりする事故も、タブを開かないことで防ぐ。

## 原則

- 見るだけにする。ファイルの書き換えや Git の操作（ステージ、コミットなど）はしない
- 見たものは会話に入れない。Claude に渡るのは、ユーザーが引用した部分だけにする。`!` モードと違い、コンテキストを使わない
- 渡すときは出どころを付ける。ファイルなら行番号、コマンドならコマンドそのものを見出しにする
- 一時的に使う。Esc ですぐ閉じ、開き直すと前の表示に戻る
- 外部のコマンド（git、ghq、fd）は、あれば使う。なくても動く範囲を残す

## 画面の構成

パネルは 1 枚（id は `peek`）で、4 つの表示を入力欄の上の帯で切り替える。パネルを表示ごとに分けると Claude Code 本体のタブが出るが、帯からはどのタブが表示中か確実に分からず、帯のボタンを表示に合わせられないため。表示ごとの状態（開いているファイル、ツリーの開閉、選んだコミット、最後のコマンド）は、切り替えても残す。

```
[ファイル] ツリー  Git  コマンド │ [選択を引用]  ソース  変更 +3 −1  @パス  ← 戻る  閉じる
```

- 左に表示の切り替え、右にいまの表示の操作と、共通の「戻る」「閉じる」を置く。幅が足りなければ折り返す
- まだ一度も開いていない表示を押すと、既定の対象で開く（ツリーと Git は作業ディレクトリ、コマンドは使い方の案内）
- ボタンの文字キーは、帯にフォーカスがあるとき（ctrl+x tab かクリック）だけ効く。入力欄からは押せない。数字は使わない（空の入力欄で数字を打つと帯のボタンが押されるため）
- 帯に出る操作はいまの表示のものだけなので、表示が違えば同じキーを別の操作に使う（`a` はファイルとツリーでは「@パスを入れる」、Git では「コミットを入れる」）

| 表示 | 帯の操作 | キー |
| --- | --- | --- |
| 共通 | 選択を引用 | `q` |
| ファイル | ソース / 整形（`.md` のとき）、変更 +a −r（変わったとき）、@パスを入れる | `s`・`d`・`a` |
| ツリー | ツリーを引用、@パスを入れる、コピー | `t`・`a`・`c` |
| Git | コミットを入れる（コミットを選んだとき）、更新 | `a`・`r` |
| コマンド | 出力を引用、再実行、コピー | `t`・`r`・`c` |
| 共通 | ← 戻る（戻り先があるとき）、閉じる | `b` |

パネルは `columns: 100`、入力欄の上では内容の高さを `rows` に指定し、`closeOnEscape` を付けて開く。dark 系のテーマでは背景を `transparent` にする（md-review と同じ）。

## コマンド

### `/peek [対象]`

引数から表示を決める。上から順に当てはめる。

| 引数 | 表示 | 例 |
| --- | --- | --- |
| なし | 最後に見ていた表示を開き直す。一度も開いていなければ作業ディレクトリのツリー | `/peek` |
| `!` で始まる | コマンド | `/peek !glo -20` |
| `git` | Git | `/peek git` |
| 実在するファイル（末尾に `:行` か `:行-行` を付けてよい） | ファイル | `/peek src/a.ts:120`、`/peek ~/notes/x.md` |
| 実在するフォルダー | ツリー | `/peek docs`、`/peek ~/repos/github.com/pentim/shok` |
| それ以外 | 候補からあいまいに探し、いちばん合うものの種類で開く | `/peek plan`、`/peek shok` |

あいまいに探す候補は、次の順に並べてから `rank`（ファイル名に含む → パスに含む → 名前にあいまいに一致 → パスにあいまいに一致）で絞る。同じ順位なら並べた順を保つ。

1. 会話に出てきたファイル（Claude が Read・Write・Edit したもの、返答の本文に出てきたパス。`path:行` の形も拾う）
2. プロジェクトのファイル（`git ls-files`、git の外では fd）
3. ghq の repo（`ghq list -p`。ghq がなければ出さない）

何も合わなければ「見つかりません」と、指定の仕方を返す。

### `/md [名前]`

md-review からの互換のために残す。候補を `.md` に絞る点と、引数なしで「会話に出てきた最新の `.md`」を開く点が `/peek` と違う。

### 引数の補完

`/peek ` に続けて打つと、次を候補に出す（最大 10 件）。

- `!` で始まるとき: 最近実行したコマンド（`$.store` にセッションをまたいで 20 件まで残す）
- それ以外: `git`（打った文字が `git` の先頭と合うとき）と、あいまい検索の候補。候補の行は、名前・フォルダー・種類（ファイル・フォルダー・repo）を出す

### 短い別名（設定で有効にする）

`/tree [フォルダー]` と `/git` を、設定 `shortCommands` を有効にしたときだけ登録する。公開するプラグインが一般的な名前を占有すると、ほかのプラグインやスキルとぶつかるため、既定では作らない。

## 表示ごとの設計

### ファイル

md-review のファイル表示を、`.md` 以外のテキストファイルにも広げる。

- `.md`・`.markdown` は整形して表示し、「ソース」で行番号付きの書いたままの表示に切り替える。ほかのファイルは、いつも行番号付きのソースで表示する（`Code` 要素に `path` を渡し、拡張子から色分けの言語を決めさせる）
- 前回の送信からの変更を差分で表示する（すべての種類のファイル）。ディスク上の変更を 1 秒ごとに確かめて追う。ディスクから消えたファイルは表示を残し、消えたことを先頭に示す
- `.md` の相対リンクをクリックすると、そのファイルを開く（md-review と同じ）
- バイナリのファイル（NUL を含む）と、4 MiB を超えるファイル（読み込みの上限）は開かず、理由を出す。90,000 文字を超える部分は表示しない（1 回の描画の上限が 100,000 文字のため）

**行を指定して開く**: `path:120` や `path:120-130` で開いたときは、ソース表示にして、その行を先頭に送り、背景色で示す。`Code` 要素を 3 つ（指定の行の前、指定の行、後）に分け、指定の行の `Code` を背景色付きの `Box`（キー `peek-line`）で包む。`$.ui.open` はパネルを描いてから返るので、そのあと `$.ui.scroll({ to: { key: 'peek-line' }, in: 'peek', block: 'start' })` で 1 回だけ送る（断られても開いたままにする）。先頭には「120 行目」のように行を出す。開いた直後のパネルでこのスクロールが効くかは、実際の画面でまだ確かめていない。行を指定していないときは `Code` を 1 つで描く。

**引用の見出し**: `docs/plan.md:12-14`。整形した表示では、選んだ文字列を元のファイルから探して行を決める（`locate`）。ソース表示では、選択に入った行番号を読み取る（`ungutter`）。行が分からないときはファイル名だけを付ける。

**@パスを入れる**: 表示中のファイルの `@パス` を入力欄に入れる。作業ディレクトリの中なら相対パス、外なら `~/` か絶対パスにする。

### ツリー

`la`・`tree`・`pwd` と、別の repo のパスを調べる作業の代わり。

- 先頭に、ルートの絶対パスと、Git の repo ならブランチを出す
- 一覧は `$.fs.list` で取る（外部のコマンドは要らない）。フォルダーを先に、名前順（大文字小文字を区別しない）に並べる。隠しファイルも出し、`.git` だけは出さない
- 最初に開くのは、ルートと、その直下のフォルダーのうち行の合計が 200 を超えない範囲。フォルダーをクリックすると開閉する。1 つのフォルダーの項目が 100 を超えるときは、残りを「…ほか N 件」の行にまとめ、押すと全部出す。表示する行の合計は 1,000 までにする
- Git の repo の中では、`git status --porcelain=v1 -z` で状態の印（`M`・`A`・`D`・`?`）をファイルの右に付け、変更を含むフォルダーには点を付ける。.gitignore の対象は `git ls-files -z --others --ignored --exclude-standard --directory` で調べ、薄い色で畳んだまま出す（以前、無視されたフォルダーの中を Claude に伝えにくかったため）
- 行は 1 行ずつボタンにする。フォルダーは開閉し、そのフォルダーを「選択中」にする。ファイルはファイル表示で開く（「戻る」でツリーに戻る）
- 帯の「@パスを入れる」は選択中のフォルダー（なければルート）の `@パス` を入れる。「ツリーを引用」は、見えているツリーを見出し `tree docs/` を付けたコードブロックで入力欄に入れる。「コピー」は同じ文字列を `$.ui.copy` でクリップボードに入れる
- ツリーの文字列は `tree` と同じ罫線（`├──`・`└──`・`│`）で作り、状態の印も含める
- ツリーの表示中は 5 秒ごとに、開いているフォルダーと Git の状態を読み直す。Claude のターンが終わったときと、Claude がファイルの編集やシェルのコマンドを実行したあとにも読み直す

### Git

`gs`・`glo` の代わり。作業中の変更の差分は、組み込みの `/diff` に任せる。

- **先頭**: ブランチ、upstream とその差（`↑2 ↓0`）、stash の数。`git status --porcelain=v2 --branch --show-stash -z` の `#` の行から読む
- **状態**: ステージ済み・未ステージ・未追跡に分けてファイルを出す。行はボタンで、押すとファイル表示で開く（削除したファイルは開けない旨を出す）。末尾に「差分は /diff で見られます」と薄く出す
- **履歴**: `git log --graph --format=%x1f%h%x1f%D%x1f%s%x1f%ar -n 40 --color=never` の 40 件。グラフの線は薄く、ハッシュ・参照（ブランチやタグ）・件名・経過時間を色分けする。コミットの行はボタンで、押すとそのコミットの詳細を出す
- **コミットの詳細**: 作者・日時・本文、変更したファイルと行数（`git show --stat`）、ファイルごとの差分。差分は `git show --format= --patch --no-color --no-ext-diff --diff-merges=first-parent` をファイルごとに分け、それぞれを `Code` 要素の diff 表示で描く。マージコミットは最初の親との差分にする（`/diff` では過去のコミットを見られないので、ここで埋める）
- **コミットを入れる**: 選んだコミットを `abc1234（件名）` の形で入力欄に入れる
- git は `GIT_OPTIONAL_LOCKS=0` で動かす。`git status` が index のロックを取って、Claude が同時に動かす git とぶつかるのを避けるため
- 読み直しは、Git の表示中は 5 秒ごとに状態を読み、`branch.oid` か参照が変わったときだけ履歴も読む。ほかに、開いたとき、Claude のターンが終わったとき、Claude がシェルのコマンドを実行したあと、「更新」を押したとき
- repo の外では「Git のリポジトリではありません」と出す

### コマンド

上のどれにも当てはまらない、タブで実行していたコマンドの代わり。

- `/peek !コマンド` を、ユーザーのシェル（`$SHELL`、なければ `/bin/sh`）の対話モード（`-ic`）で、作業ディレクトリで実行する。対話モードにするのは、`.zshrc` などで定義したエイリアスと関数（`gs`・`glo`・`la` など）を使えるようにするため
- 実行時に環境変数 `PEEK=1` を渡す。シェルの設定で Claude Code の中ではエイリアスを切っている場合（`CLAUDECODE` を見る書き方）、その条件に `PEEK` を加えれば、peek の中でだけエイリアスが効く
- 標準入力は空、時間の上限は 30 秒（設定 `commandTimeoutSeconds`）。実行が断られたとき、上限まで経っていれば止めたことを、そうでなければ実行できなかったことと理由を出す（エンジンの断りの文面には頼らない）。`tail -f` や開発サーバーのように終わらないコマンドは、今回は扱わない
- 出力から、ANSI のエスケープ（色や画面の制御）と、タブと改行以外の制御文字を取り除く。行の中の `\r` は、最後の `\r` より後だけを残す（進捗表示の上書きを再現する）。描画できる文字に限るため
- 端末のない対話シェルが出す警告は捨てる。サンドボックスの中で試したときは `can't change option: zle` が出た。サンドボックスの外で動く mod では違う警告が出るかもしれないので、実際の画面で確かめて加える
- 先頭にコマンドと終了コード（0 以外は色付き）を出す。標準出力を `Code` 要素で出し、標準エラー出力があればその下に分けて出す
- 実行したコマンドは `$.store` に 20 件まで残し、補完に出す。Claude の返答に出てきたコマンドを自動で実行することはしない
- 注意: `!` モードと同じく、エージェントのサンドボックスの外で動く

## 共通の仕組み

### 引用

選択の出どころによって見出しを付け、引用として入力欄の末尾に足す（下書きとの間は空行で区切る。md-review と同じ）。

| 出どころ | 見出し |
| --- | --- |
| ファイル | `docs/plan.md:12-14`（行が分からなければ `docs/plan.md`） |
| ツリー | `tree docs/` |
| Git の状態 / 履歴 / コミットの詳細 | `git status` / `git log` / `git show abc1234` |
| コマンド | `$ ls -la` |

`$.ui.selection()` が `requestId` を返したときは、選択は会話の中にあるので、見出しを付けずに引用する。`requestId` がないことは、会話の外（パネル）の選択だけでなく、会話の複数の行にまたがる選択でも起こる。そのため、ないことからはパネルの選択だと決められず、次の文字列の照合で判断する。それ以外は、いまの表示の文字列の中から選択を探し、見つかればその出どころの見出しを付ける。見つからなければ、ファイル表示ではファイル名だけを付け、ほかの表示では見出しを付けない。

### 戻る

表示をまたいだ履歴を 1 本持つ。リンクやクリックで移ったとき（ツリーからファイル、Git からファイル、`.md` のリンク、履歴からコミットの詳細）に、移る前の場所を積む。`/peek` や `/md` で開いたときは履歴を空にする。戻り先が読めなければ、その項目を捨ててその旨を出す。

### 読み直し

`session.start` で 1 秒ごとのタイマーを 1 つだけ動かし、表示ごとに次を判断する。読み込みが重ならないよう、前の読み直しが終わるまで次は始めない。

| 表示 | 間隔 | 条件 |
| --- | --- | --- |
| ファイル | 1 秒 | ファイルを開いている間。更新時刻が変わったときだけ読む |
| ツリー | 5 秒 | パネルが表示中（`$.ui.panes()` の `isShown`）で、ツリーを表示しているとき |
| Git | 5 秒 | 同上、Git を表示しているとき |
| コマンド | なし | 「再実行」を押したときだけ |

加えて、Claude のターンが終わったときと、Claude の Bash・Write・Edit の実行後に、ツリーと Git を「古い」と印を付け、次のタイマーで読み直す。

### 言語

md-review と同じ。設定 `language`（`auto`・`en`・`ja`）。`auto` は Claude Code の `language` の設定、次にロケール、どれもなければ英語。

## 状態の持ち方

状態はファイルごとに 1 つの値（atom）にまとめ、その値を読み書きするのはそれを宣言したファイルだけにする（Claude Code が mod の読み書きする値を、ファイルごとの atom から一覧にするため）。

| 値 | 中身 |
| --- | --- |
| `nav` | パネルが開いているか、いまの表示、戻る履歴 |
| `file` | パス、ラベル、本文、更新時刻、変更の基準（前回の送信時の本文）、消えたか、ソース / 整形 / 変更、指定の行 |
| `tree` | ルート、開いているフォルダー、選択中、フォルダーごとの一覧、Git の印、無視の対象、読んだ時刻 |
| `git` | repo のルート、状態、履歴、選んだコミットとその詳細、読んだ時刻 |
| `command` | コマンド、作業ディレクトリ、標準出力、標準エラー出力、終了コード、時間、実行した時刻 |
| `offer` | 返答が名前を出した `.md`（md-review と同じ） |

表示を分けて持つのは、5 秒ごとの Git の読み直しが、ほかの表示の描画を巻き込まないようにするため。

## ファイル構成

```
hooks/
  register.tsx      イベントとコマンドをつなぐだけ
  nav.ts            いまの表示と戻る履歴、パネルを開く・閉じる
  views/file.ts     ファイル表示の状態と操作（md-review の doc.ts）
  views/tree.ts     ツリー表示の状態と操作
  views/git.ts      Git 表示の状態と操作
  views/command.ts  コマンド表示の状態と操作、実行の履歴（$.store）
  find.ts           対象の解決とあいまい検索の候補（会話・プロジェクト・ghq）、ファイルの読み込み
  prompt.ts         入力欄への引用と @ の追加
  ui/*.tsx          パネルと帯、表示ごとの描画
  pure/
    paths.ts        パスの解決とラベル、会話に出たファイル、候補の並べ替え
    quote.ts        引用の見出しと、選択した文字列の行の特定
    markdown.ts     リンク、front matter、描画の上限での切り詰め
    diff.ts         行の差分と hunk
    git.ts          git の出力の解析（status v2、グラフ付きの log、show のファイルごとの分割）
    tree.ts         一覧から行とツリーの文字列を組み立てる
    terminal.ts     ANSI と制御文字の除去、\r の処理
    target.ts       /peek の引数の解析（!、git、path:行）
  messages.ts       英語と日本語のメッセージ、言語の判定
```

## 設定（userConfig）

| 項目 | 値 | 既定値 |
| --- | --- | --- |
| `language` | `auto`・`en`・`ja` | `auto` |
| `shortCommands` | `/tree` と `/git` も登録する | `false` |
| `commandTimeoutSeconds` | コマンドの時間の上限（1〜600） | `30` |

## 制限と安全

- 読むだけで、書き込みは `$.store` のコマンドの履歴だけ
- コマンド表示は、ユーザーが打ったコマンドだけを実行する。サンドボックスの外で動くのは `!` モードと同じ
- 描画は 1 回 100,000 文字までなので、本文・出力・差分は 90,000 文字で切り、切ったことを先頭に出す。差分は hunk の切れ目で切る
- 外部のコマンドは、git（ツリーの印、Git 表示、プロジェクトのファイル）、ghq（repo の候補）、fd（git の外のファイルの候補）。どれもなければ、その部分を出さずに動く

## テスト

- 純粋な関数（`pure/` と `quote.ts`）は、直接テストする。git の出力の解析は、実際の出力の例（リネーム、未追跡、upstream なし、detached HEAD、マージを含むグラフ、空の repo）で確かめる
- 表示ごとに、Claude Code のテストキットで動きを確かめる。`process.run` は argv で振り分けて、git・ghq・シェルの出力を差し替える。`$.fs.list` も差し替える。読み直しは模擬の時計を進めて確かめる
- テストキットでは確かめられないものは、実際の画面で確かめる（下の一覧）

### 実際の画面で確かめること

- 行を指定して開いたとき、その行まで送られ、背景色で示されるか
- ツリーと履歴の行をボタンにしたとき、クリックしやすく、描画が重くないか（1,000 行）
- `$SHELL -ic` の起動にかかる時間と、警告がほかに出ないか
- 組み込みの `/diff` のパネルと同時に開いたときの、タブの切り替え
- dark 以外のテーマでの色

## やらないこと

- 作業中の変更の差分。組み込みの `/diff` がファイルの一覧、ターンごとの変更、`ask` ボタンまで備えている
- ファイルの編集と Git の操作
- 送信で自動で閉じる動き。Claude の修正を横で確かめ続けることが多いため
- 終わらないコマンドの出力を流し続ける表示（`tail -f` など）。必要になれば `$.process.spawn` で足す
- コマンドの出力の色。今回は取り除き、必要になれば ANSI の色を `Text` の色に置き換えて足す
